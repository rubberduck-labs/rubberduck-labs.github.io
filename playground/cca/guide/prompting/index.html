Prompting & structured output20% of the exam

Remember

  • Explicit criteria beat "be conservative". Say what to report and what to skip, with an example per severity.
  • Few-shot examples show reasoning on the ambiguous cases. Guide: 2–4. Docs: 3–5. Varied beats many.
  • Schemas stop syntax errors, not wrong values. Validate sums and fields yourself.
  • Nullable fields stop invented values. Enums get "other" plus a detail field.
  • Retry with the document, the failed output and the exact error. It won't help if the data isn't there.
  • Batches: about 50% cheaper, up to 24 hours, no tool calls mid-request. Never for something someone waits on.
  • Review with a fresh instance. It catches more than self-review or more thinking.
  • Long documents first, question last. Quote the relevant parts before answering.

Don't mix up

Syntax error: JSON doesn't parse. Schemas prevent it.Semantic error: totals don't add up. You must check.
Batches: cheap, slow, no waiting user.Synchronous API: someone is waiting.
"Be conservative": barely changes precision.Explicit categories: changes precision.
Self-review: same reasoning, same blind spots.Independent instance: fresh eyes.

Test yourself

Answer in your head, then check.

  • Reviews have too many false alarms. Fix?Show answer

    Explicit report/skip criteria with examples; switch off the noisiest category while you fix it.

  • The schema makes Claude invent missing values. Fix?Show answer

    Make those fields nullable.

  • Line items don't add up. What goes in the retry?Show answer

    The document, the failed extraction and the specific validation error.

  • Can a pre-merge check use Batches?Show answer

    No. It blocks someone; use the synchronous API.

  • How many few-shot examples?Show answer

    Guide 2–4, docs 3–5. More important: varied, with reasoning for ambiguous cases.
