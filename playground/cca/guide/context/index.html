Context & reliability15% of the exam

Remember

  • Case facts never get summarised. Amounts, dates, IDs and promises go in a block sent every time.
  • Trim tool output to the fields that matter. Key findings first; the middle of long input gets missed.
  • Escalate on an explicit request (at once), a policy gap or no progress. Not on mood or self-rated confidence.
  • Several matches? Ask for another identifier. Never guess.
  • Retry locally, then report: failure type, what was tried, partial results, alternatives.
  • Long exploration: scratchpad files, subagents for verbose searches, manifests for recovery, /compact when full.
  • 97% overall can hide a bad segment. Measure per document type and field; sample high-confidence results too.
  • Keep claim → source → date through synthesis. Report conflicting figures with both sources.

Don't mix up

Customer asks for a human: escalate now.Customer is frustrated: offer to solve, escalate if they ask again.
Access failure: retry decision needed.Empty result: a valid answer.
Overall accuracy: one number.Per segment: where it actually fails.
Conflicting figures: show both with sources.Different years: not a conflict.

Test yourself

Answer in your head, then check.

  • Summaries turn "$142.50 by Friday" into "refund discussed". Fix?Show answer

    A case-facts block outside the summary, sent with every request.

  • Two customers match. What does the agent do?Show answer

    Ask for another identifier.

  • A subagent's query times out twice. What does it return?Show answer

    Failure type, the query, partial results and alternatives.

  • Accuracy is 97%. Can you stop human review?Show answer

    Not until you've checked accuracy per document type and field.

  • Two sources disagree on a figure. What goes in the report?Show answer

    Both figures, their sources and dates, marked as conflicting.
