Tools & MCP18% of the exam

Remember

  • The description picks the tool. Say what it does, its input, edge cases, and when to use it instead of a similar one.
  • Overlapping tools get renamed or split, not "choose carefully".
  • Errors are structured: isError, a category (transient, validation, business, permission) and whether to retry.
  • Empty is not failed. No results is a success; a timeout is an error.
  • 4–5 tools per agent, scoped to its role. One narrow cross-role tool for frequent needs.
  • tool_choice: auto may answer in text, any forces some tool, a named tool forces that tool.
  • Team MCP servers in .mcp.json with ${TOKEN}; personal ones in ~/.claude.json.
  • Glob finds files by name; Grep finds text in files. If Edit isn't unique: Read, then Write.

Don't mix up

Glob: file names and paths.Grep: text inside files.
.mcp.json: project, committed, shared.~/.claude.json: user, personal, not shared.
any: must call some tool.Named tool: must call that tool.
Empty result: the search worked, nothing matched.Access failure: the search didn't run.
Resource: data the app attaches.Tool: an action the model calls.

Test yourself

Answer in your head, then check.

  • Claude mixes up two similar tools. First fix?Show answer

    Rewrite (or rename) both descriptions so each says when to use it instead of the other.

  • What should a tool error tell the agent?Show answer

    isError, the category, and whether a retry can help.

  • A search finds nothing. Error or success?Show answer

    Success with an empty list. A timeout is the error.

  • Team GitHub MCP server with personal tokens. Where?Show answer

    .mcp.json in the repo, with ${GITHUB_TOKEN} from each developer's environment.

  • Find every *.test.tsx file. Which tool?Show answer

    Glob.
