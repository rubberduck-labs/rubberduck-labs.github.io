Agent architecture27% of the exam

Remember

  • Loop on the stop reason. Continue while stop_reason is tool_use; stop on end_turn. Never on wording, a text block or a turn cap.
  • Subagents start empty. Everything they need goes in their prompt: findings, sources, goal, output format.
  • Spawn with the Agent tool (formerly Task). It must be in allowedTools. Several calls in one response run in parallel.
  • The coordinator is the hub. It picks subagents, splits scope, checks for gaps and routes all messages.
  • Guarantees live in code, not prompts. PreToolUse blocks a call; PostToolUse fixes a result.
  • Chain when the steps are known; plan adaptively when they aren't. Big reviews: per file, then across files.
  • Sessions: --resume when old results still hold; fresh session plus summary when they're stale; fork_session to compare two ideas.
  • Handoffs to a human carry customer ID, what was checked, root cause and the recommended action.

Don't mix up

PreToolUse: before the call. Can block it.PostToolUse: after the call. Can change the result.
Prompt chaining: fixed steps, known in advance.Orchestrator-workers: steps decided at run time.
--resume: continue when earlier results still hold.fork_session: branch from the same point to compare.
Prompt rule: usually followed.Hook or gate: always enforced.

Test yourself

Answer in your head, then check.

  • Your loop ends when Claude writes "Done". What's wrong?Show answer

    Loops stop on stop_reason, not on wording. Continue on tool_use, stop on end_turn.

  • The coordinator never delegates. First thing to check?Show answer

    Whether allowedTools includes the subagent tool (Agent, formerly Task).

  • How do two subagents run at the same time?Show answer

    The coordinator emits both subagent calls in one response.

  • Refunds above $500 must never run automatically. How?Show answer

    A PreToolUse hook that blocks the call and tells the agent to escalate.

  • The files changed since yesterday's session. Resume or start fresh?Show answer

    Fresh session with a summary if most results are stale; resume and name the changed files if only a few changed.
