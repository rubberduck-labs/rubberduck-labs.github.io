The exam

  • 60 questions in 120 minutes. Some ask for one answer, some for several; each says how many.
  • 4 scenarios drawn from 6: customer support agent, code generation with Claude Code, multi-agent research, developer productivity, Claude Code in CI, structured data extraction.
  • Pass: scaled score 720 of 1,000. Weights: agents 27%, tools & MCP 18%, Claude Code 20%, prompting 20%, context 15%.

Agent architecture 27%

  • Loop: continue while stop_reason is tool_use; stop on end_turn. Append the full assistant content and the tool results. Don't stop on wording, on a text block or on an iteration cap.
  • Coordinator: hub and spoke. It picks the subagents a query needs, splits scope to avoid overlap, checks the synthesis for gaps and re-delegates. All traffic goes through it.
  • Subagents: start empty. Put findings and sources in the prompt. Allow the spawning tool (Agent, formerly Task). Several calls in one response run in parallel. Give goals and quality criteria, not steps.
  • Guarantees need code: prompts fail sometimes. Use hooks or gates for order and limits: PreToolUse blocks a call, PostToolUse normalises results.
  • Decomposition: fixed chain for predictable work; adaptive plan for open-ended work. Big reviews: per-file passes, then a cross-file pass.
  • Sessions: --resume <name> when earlier results still hold, and say which files changed. Fresh session with a summary when they're stale. fork_session to compare approaches.
  • Handoff to a human: customer ID, what was checked, root cause, recommended action.

Tools & MCP 18%

  • Descriptions choose the tool. Say what it does, its inputs, edge cases, and when to use it instead of a similar tool. Rename or split overlapping tools. Check the system prompt for wording that pulls toward one tool.
  • Errors: set isError with a category (transient, validation, business, permission) and whether it's retryable. An empty result is a success, not a failure.
  • Distribution: 4–5 tools per agent, scoped to its role. Add a narrow cross-role tool for frequent needs.
  • tool_choice: auto may answer in text, any forces some tool, a named tool forces that one. See the compatibility note.
  • MCP in Claude Code: team servers in .mcp.json with ${TOKEN} expansion; personal ones in ~/.claude.json. Expose catalogues as resources. Prefer existing community servers for standard systems.
  • Built-in tools: Glob finds files by name, Grep finds text in files. If Edit can't find a unique match, Read then Write. Explore from entry points; don't read everything.

Claude Code 20%

  • CLAUDE.md: user (~/.claude/CLAUDE.md, not shared), project (committed), subdirectory. @path imports keep it modular. /memory shows what's loaded.
  • Rules: .claude/rules/*.md with paths: ["**/*.test.tsx"] load only for matching files, across directories.
  • Commands and skills: team ones in .claude/commands/ and .claude/skills/, personal ones in ~/.claude/. Skill frontmatter: context: fork isolates output, disallowed-tools removes tools, allowed-tools pre-approves tools, argument-hint asks for input. Skills load on demand; CLAUDE.md always loads.
  • Plan mode for large, multi-file or architectural work; direct execution for small, clear fixes. The Explore subagent keeps discovery out of the main context.
  • Iterating: 2–3 input/output examples, tests first, the interview pattern. Send interacting problems together, independent ones one by one.
  • CI: -p, --output-format json --json-schema, project context in CLAUDE.md. Review with a separate instance, and pass earlier findings so only new issues are reported.

Prompting & structured output 20%

  • Explicit criteria beat "be conservative" or confidence thresholds. Define what to report and what to skip, with an example per severity. Switch off a category with many false alarms while you fix it.
  • Few-shot: targeted, varied examples that show the reasoning for ambiguous cases. The guide says 2–4; the prompting docs say 3–5.
  • Schemas remove syntax errors, not semantic ones. Make missing fields nullable, add "other" plus a detail field to enums, and include normalisation rules.
  • Retries include the document, the failed output and the specific error. They don't help when the information isn't there. Extract a calculated total next to the stated one to catch mismatches.
  • Batches: about 50% cheaper, up to 24 hours, no tool calls mid-request. Not for anything someone waits on. Resubmit only failed custom_ids.
  • Review: an independent instance catches more than self-review or more thinking.

Context & reliability 15%

  • Case facts: keep amounts, dates, IDs and promises in a block that is never summarised. Trim tool output to the fields that matter. Put key findings first; models miss the middle of long inputs.
  • Escalate when the customer asks for a human (right away), when policy doesn't cover the request, or when there's no progress. Not on sentiment or self-rated confidence. Several matches: ask for another identifier.
  • Errors between agents: retry transient failures locally; otherwise pass on the failure type, what was tried, partial results and alternatives. Never report a failure as an empty result.
  • Long exploration: scratchpad files for findings, subagents for verbose searches, manifests for crash recovery, /compact when context fills.
  • Human review: measure accuracy per document type and field, not just overall. Sample high-confidence results too. Calibrate confidence on labelled data.
  • Provenance: keep claim-to-source links and dates through synthesis. Report conflicting figures with both sources.

Exam guide vs current models

  • The guide teaches tool_choice any and forced tools. Claude Opus 5.5 and Sonnet 5.5 reject both; use auto with clear instructions, or structured outputs (output_config.format).
  • The guide calls the subagent tool Task; current SDKs call it Agent.
  • Assistant prefill is rejected on current models; use structured outputs.
  • The guide describes a skill's allowed-tools as a restriction. In current Claude Code it pre-approves tools; disallowed-tools removes them.
